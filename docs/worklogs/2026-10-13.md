**择优判据**（`selection/ChapterRepairCandidateSelection.ts`，按优先级）：
1. candidate 复验未有效核对 → 原稿
2. candidate 引入**新的 severe code** → 原稿（`detectNewSevereProseFindings` 只比 code，**不含专名错误**）
3. candidate 新增/扩大未兑现义务 → 原稿
4. `candidate.pass && !original.pass` → candidate
5. **`candidateBlocking < originalBlocking` → candidate**
6. candidateMissing 更少 或 `candidateIssueCount < originalIssueCount` → candidate
7. 否则原稿（`original_retained_no_clear_improvement`）

→ 第一章：原稿 blocking 3，sepia 收尾后候选稿 blocking 仍 3（修掉 3 条又新增 2 条）→ 不满足第 5 条 → **保留原稿 → 3 条 finding 永久残留 → 跨章污染 + 自锁**。
→ 若去掉 sepia 收尾：候选稿 blocking 0 < 3 → 命中第 5 条 → **采纳 → finding 清零 → 不残留、不自锁**。

**结论**：`repairDraftContent` 应回退为纯 `runChapterRepairText`（即撤销本轮 da374ebc 对该函数的「串联」改动）。草稿后那一轮 sepia 保留（sepia 的核心价值所在）。收益：消除专名改写、每章多留 15%~20% 篇幅、破解自锁与跨章残留、每章省 3 次调用约 90s。
